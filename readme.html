Overview
This page explains the main workflow of the app from tour setup to final lock.
The app is built around shared calendars, guide availability, tour creation, participant tracking and final invoicing.
Tour Configuration
Tour templates: all bookable tours are created in Tour Configuration.
Pre-paid: use this when the tour is invoiced. You define ticket price and one or more platforms, each with its own commission, invoice requirement and email.
Free tour: use this when guests pay the guide directly. In this case no invoice is generated from the tour lock. Platforms still exist, but their value is used as the fee per participant owed to the platform.
Shareable / Private: shareable tour types can be used by guides sharing the same calendar. Private types still block conflicts but their details stay hidden from the other guide.
Share Calendar
Share My Calendar: one guide can invite another by email.
Invitation flow: the second guide receives the invitation in the Share screen and must accept it before the calendar becomes shared.
Shared work: once accepted, both guides can see the same calendar, coordinate bookings and follow the same tour schedule.
Notifications: share requests and accepted shares trigger push notifications when notifications are enabled.
Availability And Booking
Availability: each guide must mark available days in My Availability.
Important: if a guide is not marked available on a day, that guide will not appear in the booking list for that day.
Create Tour: on the main calendar, pick a day, choose a start time, select the guide and select the tour type.
Pending tours: if you create a tour for another guide, it is created as pending until that guide accepts it.
Accepted tours: once accepted, the tour becomes active and appears as confirmed in the calendar.
Conflict protection: the app blocks overlapping tours for the same guide.
Participants And Lock
Participants: after a tour is accepted, guides can add participants manually or import them from a screenshot.
Attendance status: each participant must be marked as arrived or no-show.
Lock participants: locking is final. After lock, participants can no longer be changed.
Validation before lock: all participants must have a status, and at least one participant must be marked as arrived.
Pre-paid tours: locking only freezes the participant list. Invoices are then created later from Manage Invoices by choosing a platform and a period.
Free tours: after lock, the guide can enter the amount received and the app shows the amount due to the platform based on the fee per participant.
